Roadmap — what's next for the engine

v0.14 just shipped the money-flipper loop (weekly auto-promote of the top fundability_score idea to a GitHub issue). The full v0.15+ plan lives in ROADMAP.md — the next three highest-leverage builds:

v0.15 · M effort

Revenue tracking via Stripe webhook

Build this first. Every money-oriented feature — persona weighting, fundability A/B, category mix tuning — is theater without ground-truth revenue flowing back to the idea row. A /api/revenue/stripe-webhook endpoint plus revenue_events + idea_outcomes tables converts the engine from "guesser" to "learner".

v0.15 · S effort

Edge-finder pre-pass

Cheapest defense against the "drumming the same drum" failure mode. Before each expand run, Haiku reads the last 30 days of category output plus current trends and emits 3–5 "fresh angles" injected as anti-tropes into the generator prompt. Big quality lift, almost zero cost.

v0.16 · L effort

Auto-scaffold the auto-promoted idea

Close the loop end-to-end. Wire the existing scaffold pipeline to the auto-promote cadence: generate a starter MVP repo, smoke tests, and an opening PR. Goes after the revenue feedback and edge-finder so the quality floor and learning signal are in place before code starts shipping.

See ROADMAP.md for all 20 proposals across the close-the-loop · idea-quality · fresh-input · owner-autonomy · durability themes.
